## 2. 项目一句话定义

负熵引擎是一个**本地可运行的个人负熵管理 MVP**，目标是将“记录事件 → 更新节点/能量池 → 生成周复盘 → 生成快照”闭环工程化。

它不是：
- 不是泛化超级 Agent
- 不是全自动人生决策系统
- 不是先做云端/多端同步的大系统
- 不是优先做预测建模、聚类、自动采集的研究项目

当前阶段为 **D0 冻结阶段**，已经完成：

## 4. MVP 目标与非目标

### 3.1 MVP 目标
做一个本地可运行 MVP，技术形态为：

- 前端：极简前端
- 后端：FastAPI
- 数据层：SQLite

必须打通以下闭环：

1. 初始化系统
2. seed D0 模型
3. 记录事件（含 delta）
4. 更新节点进度
5. 生成周复盘 markdown
6. 生成快照

### 3.2 当前明确非目标（后置）
以下功能不是 D0 必须项，不应抢占主线开发时间：

- AWDMS 自动采集
- HMM / KMeans 等统计建模
- Channel 变更辩论协议自动化
- 云端同步
- 多端同步
- 复杂推荐系统
- 自动人生规划生成器
- 全自动 traits 归纳

## 5. 核心建模总览

系统采用五模块建模：

- Body
- Mind
- Spirit
- Vocation
- Channel

但它们不是平级并列关系，而是分层结构：

### 5.1 分层关系（已冻结）
- **Body / Mind = 基础层**
- **Spirit / Vocation = 高维实现层**
- **Channel = 更高维决定性变量**

### 5.2 关键含义
- Body / Mind 负责“能量池 + 能力层”
- Spirit / Vocation 负责“目标、方向、节点、实现”
- Channel 决定资源投放方向、输出方向、优先级与重大决策倾向

---

## 6. 五大模块定义（工程语义）

### 6.1 Body
Body 不是仅指身体状态，而是两层结构：

1. **生理数据观测层**
   - 作用：用于估计基础体力池
   - 例：疲劳、睡眠、体重、运动恢复、身体耗能状态

2. **技能实践层**
   - 作用：描述身体对物质世界的干涉能力
   - 例：体能、动作执行、实践技能、体力劳动能力

### 6.2 Mind
Mind 也分两层：

1. **认知能量池**
   - 指当天可用脑力资源
   - 反映精神集中度、深度工作能力、认知疲劳度

2. **学科/认知能力层**
   - 指长期积累形成的认知能力
   - 可与 Body 技能层组合成现实实践能力

### 6.3 Spirit
Spirit 是高维实现层，不应被理解为单纯“情绪 / 热情 / 意义感”。

当前采用的更准确理解是：

> Spirit = 主体在现实关系、现实矛盾、现实实践中的站位、意识结构、价值立场与方向系统。

工程上可以理解为：
- 长期方向感
- 实践立场
- 核心矛盾回应方式
- 反异化边界
- 关键精神节点

### 6.4 Vocation
Vocation 不是“职业兴趣测试结果”，而是：

> Vocation = 在现实分工和现实约束中，主体选择的长期角色路径、能力积累路线与项目主线。

工程上可以理解为：
- 长期角色实现路径
- 主职业/主研究/主建造通道
- 长周期项目主线
- 与 Spirit 对应的现实实现通道

### 6.5 Channel
Channel 是更高维决定性变量，不是普通标签。

它影响：
- Spirit / Vocation 呈现方向
- Mind / Body 输出方向
- 技能学习方向
- 时间与资源分配
- 当下系统的主通道选择

可粗理解为“当前人生系统的主要资源投放轨道”。

## 7. 当前冻结规则

### 7.1 Level 规则（已冻结）
- Level 只对照 **Body / Mind**
- 范围：0~5
- D0 使用整数
- 后期允许小数
- 当前不追求过细

### 7.2 Skill Level 规则（已冻结）
Skill Level 是目标导向达成度，不是抽象熟练度：

- 0 = 无法达成
- 3 = 勉强达成
- 5 = 完美达成

技能结构使用树结构，不固定层数，建议通过 `parent_id` 表示层级。

### 7.3 Phase 规则（已冻结）
Phase 用于描述系统阶段，而不是临时心情。

默认 Phase 枚举：
- reconstruction
- stabilizing
- exploration
- expansion
- overload
- recovery

当前 phase：
- `reconstruction`

规则：
- 不同 Phase 对应不同 Level 期望
- 高维节点完成会改变 Level 的解释和标准
- Spirit / Vocation 关键节点可能触发阶段跃迁

### 7.4 Traits 规则（已冻结）
Traits 是系统化标签，不是随意备注。

定义：
> 行为模式、性格模式、基础神经系统特征、Mind/Body 模型特征、Spirit/Vocation 关键事件痕迹的汇总表达。

已冻结规则：
- 手动标注优先于自动归纳
- 冲突时应提示原因
- 每个 trait 应有：
  - priority
  - confidence
  - stability（fixed / evolving）

## 8. 当前已冻结节点与优先级

### 8.1 Spirit 关键节点（已冻结）
按优先级排序：

1. 构建一套自己的决策模型（可复用裁决框架）
2. 完善处理家庭关系机制（边界 + 沟通 + 能量保护）

以下目标已从 D0 Spirit 节点中移除：
- 长期异性伴侣

原因：
- 当前阶段不应让其占用 D0 核心资源
- 可后置到 exploration / expansion 或降为低频目标

### 8.2 Vocation 关键节点（已冻结）
采用 **A 策略：稳态复利型，门槛优先，冲刺后置**

门槛节点：
1. 全国大学生数学竞赛：获得国赛资格
2. 论文写作：完成一次完整流程（选题 → 写作 → 预印本/投稿 → 反馈 → 迭代）

冲刺节点（后置）：
3. 数学建模比赛：国赛奖
4. 力学竞赛：国赛奖

### 8.3 Channel 优先级（已冻结）

#### priority 5
- 负熵引擎 / 个人助手（RAG / LLM 工程）
- 考研（学硕·交叉方向）

#### priority 4
- 泰坦计划（身体管理）
- 数学建模能力培养
- 学科能力（力学物理 + 高数）

#### priority 3
- IR / 文献检索系统（降档维护）
- 具身智能仿真（降到 3）
- 高中物理授课负荷（约束通道）

## 9. 当前能量池基线（D0 样例）

在一次已记录状态中，约为：

- Body energy ≈ 2~3（D0 取整 = 2）
- Mind energy ≈ 3~4（D0 取整 = 4）

说明：
- D0 初期允许基于主观裁决录入
- 后续可增加更细致的估计逻辑
- 但当前不要因“估计不够科学”而阻断 MVP 开发

## 10. 页面与 API 边界

### 10.1 页面（已冻结为 3 页）
1. 今日记录
   - 核心：event + delta
2. 节点进度
   - 核心：Spirit + Vocation 关键节点展示与更新
3. 周复盘
   - 核心：生成 markdown 文本

### 10.2 API（已冻结的最低范围）
- events：新增 / 查询
- key_nodes：查询 / 更新
- weekly_review：生成
- seed / init：初始化与灌种

## 13. 编程工具执行协议（非常重要）

当你是 Codex / VS Code Agent / Claude Code 等编程工具时，请遵守以下规则：

### 13.1 首要目标
优先帮助项目**做通 MVP 闭环**，而不是扩展功能。

### 13.2 不要擅自做的事
不要默认加入：
- 用户系统
- 登录注册
- 云端同步
- 微服务拆分
- 向量数据库
- 自动总结 Agent 编排
- 复杂前端框架膨胀
- 预测模型
- 推荐系统

除非人类明确要求，否则这些都不是当前主线。

### 13.3 推荐的行为
当需求不明确时，优先采用以下策略：
1. 选择最保守、最小实现
2. 保证可运行
3. 保持命名清晰
4. 保持 schema 可扩展
5. 保持注释解释业务含义
6. 优先保留 D0 冻结规则

### 13.4 输出偏好
输出内容应尽量满足：
- 可直接运行
- 改动范围明确
- 文件结构清晰
- 对应字段含义明示
- 不要过度设计

---

## 14. 当前最合理的工程优先顺序

推荐顺序如下：

1. 统一数据模型与数据库 schema
2. 完成 FastAPI 最小接口
3. 完成 seed / init 流程
4. 完成事件录入与 delta 更新
5. 完成 key_nodes 展示与修改
6. 完成 weekly review 生成
7. 完成 snapshots 生成
8. 再补最小前端页面

如果前端与后端并行，依然应保证：
- 后端最小闭环优先
- 前端只做三页，不超范围

---

## 15. 成功标准（D0 完成标准）

D0 / MVP 可视为完成，当且仅当至少满足：

- 能初始化一个 D0 self model
- 能录入一条事件
- 能写入相应 delta
- 能更新至少一个关键节点进度
- 能生成一份周复盘 markdown
- 能生成一份 snapshot
- 全流程可在本地跑通
